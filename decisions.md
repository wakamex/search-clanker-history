# Decisions: searching more than Claude Code history

Goal: make the tool (written `sch` here, an alias for `search-clanker-history`) search the session history of the other agent harnesses that AOP ([/code/aop](/code/aop)) supports, where the on-disk format is known. AOP lists Codex, Claude Code, Cursor Agent, Devin CLI, OpenCode, Antigravity, Grok Build, Hermes, DeepSeek Harness, and Zcode. AOP delegates session storage to each harness and never parses transcripts, so the formats below come from inspecting the histories on this host.

## Result

The tool now searches Claude Code, Codex, OpenCode, and Hermes. `--agent` limits a search to one or more of them; without it, every agent that has history on the machine is searched. Each result header names the agent.

## Coverage by harness

| Harness | Decision | Reason |
| --- | --- | --- |
| Claude Code | Kept as is | Existing behavior, same output apart from the agent name in the header |
| Codex | Added | JSONL rollout files under `sessions/` and `archived_sessions/`; 300+ sessions on this host exercise the parser |
| OpenCode | Added | SQLite `opencode.db` with `session`, `message`, and `part` tables; text and tool parts are searched |
| Hermes | Added | SQLite `state.db` with `sessions` and `messages` tables |
| Grok Build | Deferred | `chat_history.jsonl` exists, but the two sessions on this host contain only system and user entries, so the assistant and tool shapes are unverified |
| Devin CLI | Deferred | `sessions.db` is empty on this host and transcripts are exported as ATIF files; no sample to verify against |
| Cursor Agent | Deferred | Chats are `store.db` files; the content encoding was not inspected |
| Zcode | Deferred | Model I/O rollout files and a SQLite store exist, but no format description or sample message flow was checked |
| Antigravity | Deferred | Conversations are protobuf (`.pb`) files; no decoder is available |
| DeepSeek Harness | Deferred | No session files found under `~/.dsh` |

Deferred harnesses can be added as one adapter each once a real session with assistant replies is available to test against.

## Design choices

1. `search-clanker-history` is the only codebase and the package that carries the real code. `search-claude-history` and `search-codex-history` are generated by `build_wrappers.py` and contain no code: each depends on the same version of the core, installs one command named after itself that starts the core's entry point, and sets the default scope. Users who want one agent install the wrapper for it; users who want more agents change a setting instead of installing another package.
   - The scope is resolved in this order: `--agent` for one search, then the choice saved by `--default-agents` in `~/.config/search-history/config.json`, then the agents of the installed wrapper packages, then every agent with history. `--default-agents` shows the current default, `AGENT ...` saves one, `all` saves every agent, and `reset` removes the saved choice.
   - The core finds wrappers through package metadata: each wrapper declares its default agent as an entry point in the `search_clanker_history.default_agents` group, and the core reads the names without importing anything. Detecting wrappers by distribution name was tried first and also matched the old 0.1.x code release of `search-claude-history`, which would have narrowed the default for someone who installed only the core. A design where the wrapper's own script supplied the scope was tried before that and ran the core with no default whenever the core's script won the shared `bin/sch`.
   - No package installs `sch`. Each package has one command named after it. Shipping a shared `sch` was tried first and had two problems that no packaging choice removes: `uv tool install` refuses a second tool that claims an existing `sch` without `--force`, and when two packages share an environment both write `bin/sch`, so removing one deletes the file for the other (both were checked with real `uv tool` and venv installs). A shared dependency that owns `sch` does not help, because `uv tool install X` exposes only the commands X declares. Distinct command names have neither problem. Users who want the short name make an alias, and the README and the skill write `sch` for the command and say so.
   - Earlier designs were dropped: generating packages with the other agents' code deleted, an entry-point plugin group that merged agents across packages, a lookup of neighboring uv tool environments, and a shared `sch` command. A wrapper has nothing to strip, and the plugin and lookup code existed only to combine packages that now do not need combining.
   - Settings problems never stop a search. A corrupt file, a non-list value, an empty list, or an unknown agent name gives one warning on stderr naming the file, and the rest of the settings still apply. Writes keep other saved keys and replace the file atomically, an unwritable folder is an error with the path, and an empty `XDG_CONFIG_HOME` (and the other path variables) means the default location. `--default-agents` cannot be combined with a search or `--agent`, and argparse abbreviations are off so a setting that persists is reachable only by its full name.
   - When the default hides other agents' history, an empty search or a missing-history error says which agents were not searched and where the default comes from.
   - The build backend is pinned (`hatchling==1.32.4`) because a rerun after a partial upload rebuilds the packages, and a rebuilt file that differs from the uploaded one fails it; two builds of the same commit with the same backend were checked to be byte-identical. `requires-python` is `>=3.10`: 3.9 is past end of life and the shared validation does not test it. The settings file is `%APPDATA%\search-history\config.json` on Windows and `~/.config/search-history/config.json` (or under `$XDG_CONFIG_HOME`) elsewhere. `tests/test_install.py` builds the real wheels and installs them with uv to check each package's own command, the default scope, and that removing one package leaves the other commands working.
   - Releases publish the core first, because the wrappers pin its exact version.
2. Everything stays in `cli.py`. The console entry point loads that file by path to avoid shadowing by similarly named scripts, so relative imports between modules would fail.
3. All agents are normalized into one hit record (agent, project, session, time, type, role, text, context). The display, role filter, `--tools`, `--since`/`--until`, and `-A`/`-B` code runs once for every agent.
4. JSONL histories (Claude Code, Codex) share the existing ripgrep, hyperscan, or mmap engine, now taking a list of roots. SQLite histories find candidate sessions with a case-insensitive regular expression function inside the database, then match the rendered message text in Python so that JSON field names never produce matches.
5. Without a wrapper package or a saved default, the search covers every agent with history, as before, and `--agent` is the per-search control. Naming an agent whose history is missing is an error; searching with no history anywhere is also an error.
6. Project names for Codex, OpenCode, and Hermes use the session working directory with `/` replaced by `-`, which is how Claude Code names project directories. Existing `-p` patterns therefore work across agents. Hermes sessions without a working directory show their source, such as `cli`.
7. Codex developer messages and injected user messages (the AGENTS.md block and the environment context) are skipped. They are present in every session and would match most searches without being anything the user or agent said.
8. Codex tool calls and outputs, OpenCode tool parts, and Hermes tool calls and results are classified as tool entries and hidden unless `--tools` is given, as for Claude Code.
9. History locations follow each harness's own environment variables: `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `XDG_DATA_HOME` for OpenCode, and `HERMES_HOME`. AOP's `AOP_*_SOURCE_HOME` variables are not used because they configure AOP, not the harness.
10. SQLite files are opened read-only. A database that cannot be read prints a warning and the search continues with the other agents.
11. Reasoning content is not searched for any agent, matching the existing behavior of skipping Claude thinking blocks.
12. Performance work is recorded in [performance.md](performance.md). Results are ordered oldest file first by default; `-n N` returns the N newest matches, still printed oldest first. Byte-level prefilters assume Claude and Codex write their type markers as `"type":"..."`, and tolerate one space after the colon.
13. No persistent index or cache. The measurements and the revisit trigger are in performance.md.
14. No version bump, tag, or release. Publishing is a separate decision.

## Verification

The unittest suite covers Claude Code, Codex (project from working directory, developer message and tool filtering, context lines), OpenCode, and Hermes with synthetic histories in a temporary home, and the missing-agent error. It passes. Manual runs against this host's real histories returned matches from all four agents.
