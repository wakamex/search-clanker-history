This release fixes how matches and the messages around them are displayed. The same version is published as `search-clanker-history`, `search-claude-history`, and `search-codex-history`.

- `-A N` and `-B N` now show N messages. They used to count tool messages, which are hidden unless `--tools` is given, so a question followed by tool calls often printed no reply at all. The search for those messages reads at most 1,000 lines on each side of the match.
- With `-A` or `-B`, the matching message starts with `>`, because without color it looked the same as the messages around it. Searches without `-A` or `-B` print as before.
- A regex pattern such as `deadline|due by` now shows the text around the match and highlights it. It used to show the first 400 characters of the message, which often did not contain the match.
- `-i` is accepted and changes nothing, because matching has always ignored case. The skill file said the default was case-sensitive, and that is corrected.
- The help, README, and skill now say that `-C 0` prints whole messages.

Correction to the 0.2.0 notes: "about 3 seconds instead of 13" and "under 1 second instead of 12" compared 0.2.0 with the search across all four agents before its speedups, a build that was never released. The released 0.1.3 searched only Claude Code and has no equivalent figure. [performance.md](https://github.com/wakamex/search-clanker-history/blob/main/performance.md) has the measurements, including a comparison with `grep` and `rg` on 13 GB of Codex history.
