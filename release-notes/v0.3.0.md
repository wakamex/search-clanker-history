sch now searches 12 coding agents instead of 4, can search chat logs, and can read reasoning and whole conversations from a given message. The same version is published as `search-clanker-history`, `search-claude-history`, and `search-codex-history`.

## Output change

Result headers now show local time instead of UTC, the same clock `--since` and `--until` read a time in, so a time copied from a header can be passed to `--since` as is. Anything that parses header times as UTC needs updating.

## New agents

`--agent` now also accepts:

- `antigravity`: the [Antigravity CLI](https://antigravity.google/) (`agy`), read from its JSON Lines transcripts.
- `gemini`: [Gemini CLI](https://github.com/google-gemini/gemini-cli), in both its older JSON chats and its newer JSON Lines chats, which rewrite a message by appending it again.
- `zcode`: Zcode, whose database uses OpenCode's layout.
- `grok`: [Grok Build](https://github.com/xai-org/grok-build).
- `devin`: [Devin CLI](https://docs.devin.ai/cli/index), reading each message once although Devin copies messages into every later version of a conversation.
- `dsh`: [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness), whose sessions are compressed with [Zstandard](https://facebook.github.io/zstd/) and need Python 3.14 or the `zstd` command.
- `cursor`: [Cursor Agent](https://docs.cursor.com/en/cli/overview).
- `muse`: Muse Code.

Grok Build and Cursor record no time per message, so their messages take their session's start time. A plain search covers every agent with history on the machine, as before.

## New options

- `--thinking` searches the agents' reasoning, shown as `[thinking]`, where the history keeps it as text. Codex and Muse store most reasoning encrypted and Cursor stores it redacted, so only their summaries, if any, are found.
- `--file PATH` searches a chat log instead of agent history: a `.jsonl` file of objects with `sent`, `sender`, and `text`, or a text file of `YYYY-MM-DD HH:MM SENDER: TEXT` lines. `^NAME:` matches one sender.
- `--after PATTERN` starts at the most recent message matching PATTERN and shows the messages from it on; the search pattern can then be left out.
- `-s`/`--session ID` keeps one session, by any prefix of its id.
- `-P`/`--exclude-project TEXT` leaves out projects whose name contains TEXT.
- `--json` prints one JSON object per match with the whole message text.

The output now stops quietly when a reader such as `head` closes the pipe.

Without [ripgrep](https://github.com/BurntSushi/ripgrep), the Python scanner used to copy a line once for every match on it, so a pattern that matches almost everywhere could exhaust memory. It now keeps each matching line once.
